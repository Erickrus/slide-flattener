# Slide Flattener（幻灯片拉平工具）

把拍摄角度歪斜的投影幻灯片照片，自动校正成正面、平整的截图——自动找到每张
幻灯片的四个角，矫正透视变形，并修正颜色。

---

## 这个工具是做什么的，为什么有价值

你坐在座位上、斜着拿手机拍下投影屏幕。每一张照片都有同样的问题：

- **透视畸变** —— 幻灯片是歪的梯形，而不是矩形。
- **偏色** —— 投影灯光让整个画面偏蓝。
- **对比度低** —— 投影偏暗，白色发灰、黑色发闷。
- **杂乱背景** —— 幻灯片周围是大片的暗房间、天花板、桌椅。

要把这些照片放进文档里，得在 Photoshop 里一张张手动裁剪、调色。而这个工具
可以对整个文件夹一次性自动完成：

1. **找到幻灯片的四个角** —— 通过识别屏幕"亮 + 带色偏"的特征。
2. **拉平** —— 把歪斜的四边形校正成完美的矩形（默认 16:9）。
3. **自动色彩（Auto Color）** —— 去除色偏，让白的更白、黑的更黑。

最终得到的是每一张幻灯片干净、清晰、可直接分享的副本——就好像你把原始演示
文稿导出成了图片，而不是一堆手机照片。

整个过程基本是全自动的。只有少数几张照片（角度太差、屏幕只拍到一部分、有手
挡住等）自动检测会出错，你只需要在一个小界面里**拖动角点**几秒钟就能修好——
完全不用 Photoshop。

## 快速开始

```bash
# 一次性环境准备
python3 -m venv .venv
source .venv/bin/activate
.venv/bin/pip install -r requirements.txt

# 之后每次使用
.venv/bin/python annotate.py
```

就这些。`annotate.py` 会为文件夹里的每一张图片打开一个窗口，让你浏览检查、修
正少数几张不理想的。输出结果写在 `./flattened/` 目录下。

> 在 macOS 上用 Homebrew 安装的 Python 时，请始终通过 `.venv/bin/python` 运行
> （系统自带的 Python 会拒绝 `pip install`）。

## 使用 `annotate.py`

这是你唯一需要用的命令。它会打开两个窗口：

- **`edit`** —— 照片上已经画好了检测到的幻灯片轮廓（绿色连线、红色角点）。照
  片四周留了一圈灰色边距，这样落在图片范围之外的角点也能被抓到并拖回来。
- **`preview`** —— 拉平 + 自动色彩后的结果，拖动角点时实时更新。

### 操作方式

| 操作 | 方法 |
|------|------|
| 修正某个角 | 拖动红色圆点（预览实时更新） |
| 上一张 | 点击 `PREV` |
| 下一张 | 点击 `NEXT` |
| 重新自动检测 | 点击 `RESET` |
| 切换输出形状 | 点击 `AR:16:9` —— 依次循环 `16:9 → 4:3 → 3:2 → 1:1 → 2:3 → 3:4 → 9:16 → auto` |
| 保存并结束 | 点击 `DONE`（或按 `Esc`） |

### 保存机制

- **自动保存** —— 切到另一张（`PREV`/`NEXT`/`DONE`/`Esc`）时会自动保存当前这
  张，没有单独的"保存"按钮。
- **没动过的幻灯片也没关系** —— 如果你没有拖动任何角点就跳过某张，它会按自动
  检测的结果原样保存。
- **不会循环跳转** —— `PREV`/`NEXT` 到第一张/最后一张就会停住。
- 当前的宽高比会显示在 `AR` 按钮上和标题栏里。

典型流程：一路点 `NEXT` 翻完整套幻灯片，只在某张看起来不对时停下来拖动角点，
继续往后，最后点 `DONE` 结束。

要用不同的宽高比开始，或只检查某些文件：

```bash
.venv/bin/python annotate.py --aspect 4:3
.venv/bin/python annotate.py IMG_0847.jpg IMG_0880.jpg
```

---

## 宽高比

输出形状由 `AR` 按钮（或命令行 `--aspect`）控制，默认是 **16:9**。选一个与你的
幻灯片匹配的比例即可——同一批照片可以导出成 4:3、1:1、9:16（竖屏）或 `auto`
（每张按各自实际测量到的形状）。

---

## 自动色彩（Auto Color）

拉平后的图片仍然带着投影仪造成的色偏（通常是偏蓝）。自动色彩分两步修正
（类似 Photoshop 的处理）：

1. **白平衡（灰度世界假设）** —— 缩放各通道，让平均颜色变为中性灰，从而去除
   色偏。
2. **按亮度做对比度拉伸** —— 裁剪掉 0.5% / 99.5% 的亮度百分位，再拉伸到全
   范围，让白的更白、黑的更黑，同时**不会**重新引入色偏。

## 四个角是怎么找到的

本工具的核心，是在照片里定位投影屏幕的四个角，以便把它拉平。

### 关键洞察：屏幕"亮" 且带有明显的色偏

投影屏幕很难靠亮度或边缘来找——幻灯片文字会把屏幕切碎，房间里还有其他发亮的
物体。但它有两个可靠的特征：

1. 它**亮** —— 被投影仪照亮，明显比房间更亮。
2. 它**有色偏** —— 它的光线带一种与房间环境光不同的色偏。通常偏冷/偏蓝，但
   根据投影仪和房间灯光，也可能是偏暖或偏绿。

所以工具不是把"蓝色"写死，而是**自动发现屏幕的颜色特征**：找出哪个通道对比能
最好地把明亮的屏幕和暗房间区分开，然后就用这个对比来做分割。

### 检测流程（`detect_slide_quad`）

1. **缩小图片** —— 把长边缩到 1600 像素（为了速度）；坐标最后再换算回原尺寸。

2. **分离亮区和暗区** —— 用大津阈值（Otsu）按亮度把明亮的屏幕和暗房间分开
   （如果直方图不是双峰的，就退回到按百分位分割）。

3. **自动检测主导对比** —— 对每一个两两通道差值（`B − R`、`B − G`、`G − R`），
   计算亮区均值与暗区均值之间的距离（除以该对比的散布程度做归一化）。取分离度
   最大的那个对比，并记住它的方向（屏幕在该对比上是偏高还是偏低）：

   ```python
   separation = |mean(bright) − mean(dark)| / std        # 每个对比分别计算
   dominant   = 分离度最大的那个对比
   ```

   蓝色屏幕时 `B − R` 胜出（屏幕偏高）；暖色投影仪时同样是 `B − R` 胜出，但方向
   相反；偏绿时 `G − R` 胜出。没有任何写死的颜色。

4. **二值化** —— 沿检测到的方向，用原始数值（`40 … 160`）对主导对比做阈值分
   割。用原始差值而不是 z 分数很关键：暗房间的各通道都接近 0，它那点微弱色偏
   的幅度极小，自然会被排除；而 z 分数反而会把它错误地放大。

5. **形态学闭运算** —— 用方形核（尝试 `21×21` 和 `41×41`）填掉幻灯片文字留下
   的暗洞，把屏幕连成一个实心的大块。

6. **找轮廓** —— 闭运算后掩膜里的每一个外轮廓都是一个**候选**屏幕。

7. **给每个候选拟合四边形**（`_quad_from_contour`）：
   - 先取轮廓的**凸包**，然后
   - 用递增的 epsilon（周长的 `0.02 … 0.15`）做 `cv2.approxPolyDP`，直到得到
     一个 4 点凸多边形；否则
   - 退回到 `cv2.minAreaRect`（最小外接旋转矩形）。

8. **过滤和打分** —— 丢弃面积小于整图 5% 的候选，对其余的按下面公式打分：

   ```
   score = area × exp( −((ratio − ratio_hint) / 0.35)² )
   ```

   其中 `ratio = width/height`，`ratio_hint` 是期望的幻灯片比例（默认 16/9）。
   这样会偏向形状像幻灯片的候选，同时排除那些形状不对的物体（比如宽桌子、或
   颜色很浓但形状不对的东西）。

9. **选出最佳** —— 在所有阈值和核大小下得分最高的候选胜出。

10. **亮度回退** —— 如果没有任何颜色对比找到屏幕（比如屏幕完全中性无偏色），
    就改用普通亮度（`gray > t`）再跑一遍同样的轮廓→四边形流程。

11. **角点排序** —— `order_points` 把四个点排成固定的循环顺序
    **左上、右上、右下、左下**：

    ```python
    top_left      = (x + y) 最小的点
    bottom_right  = (x + y) 最大的点
    top_right     = (y − x) 最小的点
    bottom_left   = (y − x) 最大的点
    ```

12. **换算回原尺寸** —— 除以缩小倍率，得到原分辨率下的坐标。

### 透视变换

四个角排好序之后，`cv2.getPerspectiveTransform` 把它们映射到目标矩形的四个角，
再由 `cv2.warpPerspective` 生成平整的图像。目标尺寸会兼顾所要求的宽高比和幻
灯片本身的细节。

### 为什么这比单纯的边缘/亮度检测更好

- 幻灯片背景被内容切得很碎，但屏幕的色偏在整个屏幕上都是均匀的，与内容无关。
- 颜色特征是对每张照片自动检测的，因此不依赖于某个特定投影仪的色温。
- 房间里其他发亮（甚至颜色更浓）的物体会被比例打分和亮/暗分离排除掉。
- 对阈值和核大小的扫描，能吸收不同手机、不同拍摄之间的曝光和白平衡差异。

## 换个座位或换台投影仪还能用吗？

简短回答：**换位置完全没问题；换投影仪通常也没问题。** 检测器并不假设某种特定
颜色——它会针对每张照片自动检测屏幕的色偏。它也不关心屏幕在画面里的位置、大
小、以及透视有多严重，所以：

- **换座位 / 换角度 / 换距离** → 仍然能用。屏幕只是变成一个形状不同的四边形，
  同一个又亮又有色偏的区域照样被找到。
- **凑近了拍 / 屏幕贴到画面边缘** → 仍然能检测到，而且界面留的边距能让你把跑
  出去的角点拖回来。
- **冷色/中性、暖色或偏绿的投影仪** → 都能用。检测器会在 `B − R`、`B − G`、
  `G − R` 中自动选一个最能区分屏幕和房间的，方向也是自动判断的。

唯一还需要手动处理的情况，是屏幕**和房间无法区分**——即它既不更亮、颜色也差不
多（例如明亮房间里亮度很低的投影、电视上几乎全黑的画面、或者没有点亮的彩色墙
壁）。这时自动检测没有可用的线索，你就需要在 `annotate.py` 里手动拖动角点
（手动方式在任何情况下都能用）。

## `flatten_slides.py`（可选的后台批处理引擎）

正常情况下你只需要 `annotate.py`；它在内部会 import `flatten_slides.py`，所以
两个文件要放在一起。

如果你偶尔想**完全不检查**就批量处理一个文件夹（比如你信任自动检测），也可以直
接运行这个引擎：

```bash
.venv/bin/python flatten_slides.py            # 处理当前目录所有图片
.venv/bin/python flatten_slides.py --debug    # 同时写出检测叠加图
.venv/bin/python flatten_slides.py --aspect 4:3
.venv/bin/python flatten_slides.py --manual IMG_0822.jpg   # 手动点四个角
```

`--debug` 会写出 `./debug/<name>_overlay.jpg`——把检测到的四边形画在原始照片
上，方便你一眼检查检测结果。

## 常见问题排查

- **某张幻灯片出来是错的（区域不对、被裁、歪斜）。**
  运行 `.venv/bin/python annotate.py`，在那张上拖动红色角点，然后点 `DONE`。

- **文字横着或倒着。**
  原始照片可能带了一个过时的 EXIF 旋转标记。先把原图旋转正确，或在
  `annotate.py` 里修正角点。

- **屏幕和房间无法区分（没有亮度/颜色对比）。**
  自动检测没有可用的线索。`annotate.py` 仍然能用——手动拖好四个角即可。
  （`flatten_slides.py --manual` 也提供同样的手动方式。）
